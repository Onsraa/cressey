# Facts decide; paraphrased thoughts only point

On the Claude Code agents Cressey watches, reasoning is a hidden, adaptive workspace that never reaches Cressey. **No current Claude model returns raw reasoning**, Claude Code stores reasoning blocks empty, and beside the facts of what the agent did, Cressey can read only four different objects: verbatim text written for the user, a provider-written paraphrase of the notes the agent writes between tool calls ("progress updates"), agent-written tool fields such as the Bash `description`, and an exact per-message count of hidden reasoning tokens. On Claude Opus 5.5 even that is unstable: most multi-sentence notes now travel as paraphrased updates that the MessageDisplay hook never sees, the model chooses the channel run by run (**from 2 of 5 notes to all of them reached the hook in the team's probes**), and the paraphrase turned a sourced claim into a verification the model never made. The words and token count bound to a call land in the transcript **about 0.1 s after that call's PreToolUse**, so reading them before the call runs takes a short, bounded wait or a Claude Code mod. Every thought threshold Cressey ships was calibrated on Opus 4.6, whose notes were verbatim text, so none of them transfers. The evidence supports a three-way split: take as fact what is recorded exactly (calls, arguments, results, hook events, model, effort, token counts, hand-over events, and the existence of a text credited to its true author); weigh every reading of words with a confidence measured as a benign percentile per model and channel and calibrated at session level, letting words open threads and raise alerts but take part in a hold only when a fact makes the call risky (an object used, a mandate crossed), the binding saying which call the words are about; and cut durations, signatures, silence as innocence, word-based thread closers, and agent-written fields inside the floor's action-only view.

## Claude Code agents never hand Cressey their reasoning

Reasoning is serial test-time compute. The model writes intermediate tokens and conditions on them; in Anthropic's words it "restates what is being asked, tries approaches, checks intermediate results, and abandons paths that do not hold up" ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). Math accuracy rose logarithmically with thinking tokens on Claude 3.7 Sonnet ([Anthropic: Visible extended thinking](https://www.anthropic.com/research/visible-extended-thinking)), outcome-based reinforcement learning shapes the trace, and the Frontier Model Forum asks labs not to train it to "look nice" and declines to recommend publishing it, so that developers are not pushed to sanitize it ([FMF issue brief](https://www.frontiermodelforum.org/uploads/2026/01/FMF-Issue-Brief-on-Chain-of-Thought-Monitorability.pdf)). The same brief states the limit that matters most for a fraud guard: chain-of-thought monitoring works on harms that need long serial reasoning and "will fail to catch harms that can occur without complex reasoning". Deleting a production table or using a credential found in a config file needs little reasoning, so even a perfect view of the workspace would often say little about the acts Cressey most wants to stop. The team's review already covers the faithfulness gap, a trace that omits what drove the act and never clears it ([ai-intent.md, Q1](ai-intent.md)). The new problem is that on current Claude models Cressey does not receive the trace at all.

Anthropic's documentation is unambiguous: "what you see is never the raw chain of thought", and "No `display` setting returns the raw chain of thought" ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). The API offers three display modes. **`omitted` is the default on Opus 4.7, Opus 4.8 and every 5.x model**: thinking blocks come back with an empty text field and a `signature` that carries the full reasoning, encrypted. `summarized`, the default on Opus 4.6, Sonnet 4.6 and earlier, returns a summary that a different model writes and the thinking model never sees, a design Anthropic justifies as keeping thinking's benefits "while preventing misuse". `updates`, in beta since 2026-09-01, keeps reasoning blocks empty and returns only progress-update text. Since Fable 5 (2026-06-09), requests that try to pull reasoning into visible output can also be refused with `stop_details.category: "reasoning_extraction"` ([Anthropic: Release notes](https://platform.claude.com/docs/en/release-notes/overview)), and full thinking is available only by arrangement with Anthropic's sales team. Other closed providers converged on the same design, with hidden reasoning, a billed reasoning-token count, optional summaries and encrypted state passed back ([OpenAI: Reasoning](https://developers.openai.com/api/docs/guides/reasoning); [Gemini: Thinking](https://ai.google.dev/gemini-api/docs/thinking)); only open-weight models such as gpt-oss return raw reasoning, which their makers describe as unrestricted and able to contain hallucinated content ([gpt-oss model card](https://arxiv.org/html/2508.10925v1)).

The object Cressey meets most often on Opus 5.5 is the progress update. On Opus 5.5, Sonnet 5.5 and the Fable and Mythos 5.x models, the model may write one note before each tool call, which the docs define as "a note on what the model just found and what it's about to do next, written for the person watching the agent rather than as reasoning". The model can skip any note, and what the API returns is "a summary of the progress update, normally a sentence or two", while the model keeps its full note in context ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). The docs state that reasoning summaries come from a different model but do not name what summarizes updates. Either way, an update is **two transformations away from the reasoning**: a note written for an audience, then a provider-side summary of that note. Claude Code 2.1.296 on Opus 5.5 records exactly this shape: `thinkingDisplay: "updates"`, empty reasoning blocks, and one or two sentences of update text immediately before a `tool_use` ([team session measurement, 2026-10-12](reasoning-signals-evidence.md)).

The paraphrase does not preserve meaning. When the team's research agent (Opus 5.5 in Claude Code) compared notes it wrote with what its own transcript recorded, the note "Key finding from the spec: in the lab transcripts, all 29 thinking blocks are signed and empty…" came back as "I've confirmed all 29 thinking blocks in the lab transcripts are signed but empty…": **a claim sourced to a document became a first-person verification the model never made** ([team session measurement](reasoning-signals-evidence.md)). Panfilov et al., who decoded the encrypted reasoning returned by the Anthropic, OpenAI and Google APIs, found the reconstruction "reveals approximately five times more reasoning than the provider exposes through the summary"; in 33 hand-checked math traces, summaries turned a hedged recollection into a stated value and recast a verification as an independent derivation, artifacts the authors attribute to "a less capable model summarizing reasoning produced by a more capable model" ([Panfilov et al., arXiv 2608.09867](https://arxiv.org/html/2608.09867v1)). No lab publishes whether summaries keep the signals of misbehaviour, and OpenAI's 13-evaluation monitorability suite excluded Claude because its API shares only summaries ([Guan et al., arXiv 2512.18311](https://arxiv.org/html/2512.18311v1)). The distortion runs in the direction that hurts Cressey's counter-indicators most: hedges and questions disappear, so "the agent was unsure or asked" is under-detected, while verifications can be manufactured, so "the agent checked" is over-detected.

Everything else in a thinking block is metadata. The signature's length tracks the token count, about four characters per thinking token (27,716 characters for 6,981 tokens), and the docs call it opaque ([team session measurement](reasoning-signals-evidence.md)). A `redacted_thinking` block means Anthropic's safety system redacted part of the reasoning, and a fixed sentence, "This part of the response was interrupted before it finished.", stands in for an update cut off by `max_tokens` ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). A missing thinking block proves nothing, because adaptive skipping, forced tool choice and a silent mid-turn downgrade all produce the same absence. Nor can Cressey obtain more reasoning by asking: an instruction anywhere in the agent's context (system prompt, skill, tool description, deny message) to write a scratchpad, a `<thinking>` section or a reasoning field in a tool input is a listed trigger for `reasoning_extraction` refusals on Opus 5 and 5.5, Sonnet 5.5 and Fable 5 and 5.1, with no fallback model for that category, while asking for "a short explanation, the evidence behind a result, or a summary of the actions it took" stays allowed ([Anthropic: Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)).

## Size and timing arrive as exact numbers, a tenth of a second late

On current models, adaptive thinking and the `effort` level decide the amount of reasoning; there is no token budget. At `max` the model "thinks the most readily and at the greatest depth, with no constraint on thinking length"; at `medium`, the default on Opus 5.5, it "may skip thinking for simple queries"; at `low` it "skips thinking for simple tasks" ([Anthropic: Steering thinking](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)). Effort is "a behavioral signal, not a strict token budget" that scales every output token, so lower effort also means "fewer and terser tool calls" and acting without preamble ([Anthropic: Effort](https://platform.claude.com/docs/en/build-with-claude/effort)). Inside a tool loop, "the first request after new user input typically carries most of the reasoning"; follow-up requests that only process tool results can skip thinking even at `max`, and thinking per request falls as the conversation grows ([Anthropic: Steering thinking](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)). Before it says anything about the task, size is a function of model, effort, position in the loop and conversation length.

The measurement itself is exact. `usage.output_tokens_details.thinking_tokens`, available since 2026-05-27, counts the raw reasoning rather than the summary and arrives on the final `message_delta` of a response ([Anthropic: Steering thinking](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)); Panfilov et al. found it tracks decoded reasoning about 1:1 on Claude ([Panfilov et al., arXiv 2608.09867](https://arxiv.org/html/2608.09867v1)). The team's measurement settles a point the docs leave open: **the count includes the full, unsummarized length of progress notes**, because messages that carry an update and no reasoning block still report 83–104 thinking tokens ([team session measurement](reasoning-signals-evidence.md)). Claude Code writes one transcript line per content block and repeats the message's final usage on each line, so counts must be de-duplicated by `message.id` ([Claude Code: Monitoring](https://code.claude.com/docs/en/monitoring-usage); [team session measurement](reasoning-signals-evidence.md)). Headless `stream-json` output carries only partial per-message usage, and its totals sit on a final `result` line that is missing when a run is killed, as in lab run 011950, so the transcript is the source to read ([team probe](reasoning-signals-evidence.md)).

Across about 53,000 API messages in this machine's Claude Code transcripts, the median volume per message differs by an order of magnitude between models ([team corpus count](reasoning-signals-evidence.md)):

| Model | API messages | Progress updates | Thinking tokens per message: median / p90 / max |
|---|---|---|---|
| Opus 5.5 | 39,087 | 4,527 | 119 / 1,309 / 50,307 |
| Opus 5 | 11,275 | 0 | 48 / 861 / 8,283 |
| Fable 5.1 | 1,534 | 46 | 231 / 1,759 / 15,864 |
| Opus 4.8 | 470 | 0 | 305 / 3,306 / 10,382 |
| Opus 4.6 | 179 | 0 | 0 / 601 / 16,961 |
| Sonnet 5.5 | 41 | 9 | 291 / 3,224 / 6,007 |

**No threshold on reasoning volume can be shared across models**, and the Sonnet 5.5 row rests on only 41 messages. Cressey's own lab runs show the spread inside one model: on Opus 4.6, the agent that paused and asked before deleting used 396 hidden-reasoning tokens over its whole run, and a pressure run used 12,988 ([team corpus count](reasoning-signals-evidence.md)). With four runs on different tasks, that contrast is a reason to measure, not a finding.

Reasoning sits in three places in a turn: up front, before the first text or tool block; between tool calls, where on every current model "reasoning between tool calls always appears in thinking blocks"; and, on the update models, in a separate update block that sits "immediately before the tool_use or server_tool_use block it introduces", at most one per call ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). In the stream, every thinking block closes before the `tool_use` block opens, and the message's thinking-token count arrives before the harness runs the tool. Duration adds nothing to this picture. Claude Code's `thinkingDurationMs` ran from 965 to 66,112 ms on reasoning blocks and 1–5 ms on update blocks in the research agent's session, **about 9.5–15.6 ms per thinking token, or 65–105 tokens per second** ([team session measurement](reasoning-signals-evidence.md)). Opus 5.5 generates output "more than 30 percent faster" than Opus 5 ([Anthropic: Prompting Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)), and the docs warn of "a pause of several seconds before a progress-update block opens" ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). Duration is the token count multiplied by serving speed, plus network noise.

The harness adds a lag that decides what Cressey can read before it gates a call. The team's decision log (since removed from the repo) stated that Claude Code writes a turn to the transcript only once its calls have returned. Direct measurement corrects this: **at PreToolUse, the call's `tool_use` line was not yet on disk in 4 of 4 calls, and a hook polling every 50 ms saw it land 105–108 ms after the hook started in 3 of 3**; the write is asynchronous and not held behind the hook ([team probe, Claude Code 2.1.296](reasoning-signals-evidence.md)). At PostToolUse the line was on disk after a 680 ms Bash call but not after 30 ms Read calls. The transcript's own `timestamp` fields place each update and its `tool_use` 25–40 ms before PreToolUse, but they record when a line was created, not when it was written. The hooks reference agrees that `transcript_path` is written asynchronously and can lag the conversation ([Claude Code: Hooks](https://code.claude.com/docs/en/hooks)). The update, the token count and the model bound to a call are therefore readable at that call's PreToolUse only after a wait of about 0.1–0.3 s. MessageDisplay offers no shortcut: in headless runs it fires once per message after the message completes, and no document orders it against PreToolUse. The one documented channel that streams thinking text live, ordered before the call it introduces and able to veto that call, is a Claude Code mod observing `turn.step`, an early-access API ([Claude Code: mod types](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)).

## Model, effort and harness decide which words reach Cressey

The purpose of reasoning does not change with these levers; it stays a private workspace. What changes is how much of it exists, which channel carries the visible remainder, and when that remainder can be read.

| Lever | Size | Content and channel | Timing |
|---|---|---|---|
| Model version | Median per message from 48 tokens (Opus 5) to 305 (Opus 4.8) on this machine; Opus 5.5 thinks more per turn than Opus 5 at the same level | Opus 5 and 4.8 send between-call notes as verbatim `text`; Opus 5.5, Sonnet 5.5 and Fable 5.x send most multi-sentence notes as paraphrased updates; Fable 5.1 writes few | Opus 5.5 is over 30% faster per token than Opus 5 |
| Effort | Sets depth; `low` and `medium` skip thinking on simple steps; `max` is unbounded; also scales tool calls and preambles | Fewer updates at higher effort and in long tool chains; terse, preamble-free actions at low effort | Most reasoning lands on the first request after a prompt |
| Claude Code defaults | Thinking cannot be turned off on Opus 5.5; effort `medium` unless set; `ultrathink` adds an instruction, not API effort | Empty reasoning, paraphrased updates; MessageDisplay carries `text` only | The call's transcript line lands about 0.1 s after PreToolUse |
| `showThinkingSummaries: true` | Unchanged, billed in full | Headless probe: updates came back empty and no reasoning summaries appeared; interactive untested | None measured |
| Model switch | The new model's baseline | Opus 5.5 to Opus 5 (biology) or Opus 4.8 (cyber) puts notes back into verbatim `text` | Content fallback fires PostModelSwitch; availability fallback fires nothing |
| Subagents, compaction | Separate usage per transcript | Subagent words in their own transcript; compaction replaces history with a summary | Subagent words at SubagentStop; earlier reasoning leaves the agent's context |

The model sets the channel. "On Claude Opus 5, text the model writes between tool calls comes back as text blocks. On Claude Opus 5.5, as on Claude Fable 5.1, that narration comes back as progress-update thinking blocks" ([Anthropic: Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)). The local corpus shows the switch, with 4,527 updates in 39,087 Opus 5.5 messages and none in 11,275 Opus 5 messages ([team corpus count](reasoning-signals-evidence.md)). The MessageDisplay hook that feeds Cressey's narration today carries text only: in the shipped 2.1.296 binary its `delta` is built from text blocks while thinking streams through a separate callback, and in a controlled headless probe the hook received the run's two text blocks while its three updates reached no hook at all ([team probe](reasoning-signals-evidence.md)). The split follows no length rule. With the same prompt and model, three probes sent the turn's first note as text and later notes as updates, and a fourth sent every note as text, so **MessageDisplay alone covered between 2 of 5 notes and all of them**. Style moves with the model too: Opus 5 "narrates readily during agentic work" ([Anthropic: Prompting Opus 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5)), and commentary on the Opus 5.5 system card reports heavier jargon in its reasoning alongside very low controllability ([Zvi on the Opus 5.5 system card](https://www.lesswrong.com/posts/vMNTWTDWLorDqd3LS/claude-opus-5-5-the-system-card)).

Effort sets how much visible text accompanies the work. "These models write fewer progress updates at higher effort and in long tool chains" ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)), while higher effort tends to "explain the plan before taking action" in text and lower effort acts without preamble ([Anthropic: Effort](https://platform.claude.com/docs/en/build-with-claude/effort)). **The readable channel is thinnest exactly when the agent works longest and most autonomously.** Effort itself reaches Cressey as a fact, because PreToolUse carries an `effort` field; Claude Code resolves it from the environment variable, `--effort` or `/effort`, then settings, then the model default, with `max` lasting one session and `ultrathink` adding an in-context instruction without changing the API effort ([Claude Code: Model configuration](https://code.claude.com/docs/en/model-config)).

The harness can silence a channel without raising an error. The settings reference says `showThinkingSummaries` defaults to `false`, which leaves thinking redacted, and that `true` makes summaries available ([Claude Code: Settings](https://code.claude.com/docs/en/settings-reference)); interactive sessions stopped generating summaries by default in 2.1.89 ([Claude Code: Changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). In the team's headless probe, `true` did the opposite of what a monitor needs: the transcript lost its `thinkingDisplay` field, reasoning blocks stayed empty, and update blocks came back empty, the `omitted` shape ([team probe](reasoning-signals-evidence.md)). This is one headless run; interactive behaviour was not tested. Where summaries are honoured, the docs warn that an update is "not distinguishable from a reasoning block" by its text ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)), although its position just before a `tool_use` and its 1–5 ms duration would still mark it, an untested inference.

Claude Code can also change the model underneath Cressey. Content-based fallback moves Opus 5.5 to Opus 5 for biology or to Opus 4.8 for cybersecurity, keeps the effort, and fires PostModelSwitch with `source: "auto"`; an availability fallback lasts one turn and fires no hook ([Claude Code: Model configuration](https://code.claude.com/docs/en/model-config); [Claude Code: Hooks](https://code.claude.com/docs/en/hooks)). PreToolUse carries no model field, so only the transcript gives the model of each message ([team probe](reasoning-signals-evidence.md)), and a cyber fallback puts the agent's notes back into verbatim text at Opus 4.8's volume baseline, a change Cressey sees only if it handles PostModelSwitch or reads each message's model. Subagents write their own transcripts under `subagents/agent-{agentId}.jsonl`, run in the background by default (so the parent's PostToolUse returns `async_launched` with no result), can run a different model, and deliver their final words at SubagentStop through `last_assistant_message` and `agent_transcript_path` ([Claude Code: Hooks](https://code.claude.com/docs/en/hooks); [Claude Code: Subagents](https://code.claude.com/docs/en/sub-agents)). Compaction replaces history with a model-written `compact_summary`, after which the earlier signatures, the only carriers of full reasoning, are gone from the agent's context. OpenTelemetry never carries reasoning, since `assistant_response` excludes thinking blocks and raw API bodies redact them ([Claude Code: Monitoring](https://code.claude.com/docs/en/monitoring-usage)). The advisor tool runs server-side, where no mod tool hook fires ([Claude Code: Mod events](https://code.claude.com/docs/en/plugins/mods/events)).

Cressey's calibration rests on the old shape. Every lab run used Opus 4.6 through `claude -p`, where notes were verbatim text, and the thought cut-offs (Task 8: 40 runs, 412 thoughts, jev-1.13.0) were set on that narration plus METR quotes and synthetic runs. After the N1 rewording, the case file held **9 of 21 incidents before harm with 2 false holds**, and its findings included N1 scoring high on plain narration, rationalization linking to a call only through extracted objects, and one incident with no words at all ([team corpus count](reasoning-signals-evidence.md); [thoughts-calibration.json](../../backend/data/eval/thoughts-calibration.json)). The code still tags every MessageDisplay message as `narration` and ignores `transcript_path`, `effort` and the `tool_use_id` that would bind words to calls ([team code reading](reasoning-signals-evidence.md)). On Opus 5.5 the stream differs in channel, volume and fidelity, so those cut-offs do not transfer.

## Each signal proves something different about fraud-like behaviour

The most useful outside reference is how Anthropic guards the same agent. Claude Code's auto-mode classifier "sees only user messages and the agent's tool calls" and is "reasoning-blind by design": it strips assistant prose so the agent cannot talk the classifier into a bad call and strips tool outputs as the main defence against prompt injection, and including them lowered performance on its overeagerness test set ([Anthropic: Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)). On 10,000 real actions the full pipeline reports **0.4% false positives**, but it misses **17% of 52 real overeager actions**, mostly by reading approval-like evidence in the session as consent for the action's full impact. In control benchmarks, action-only monitors catch roughly 70–83% of attacks at 1% FPR with Opus 4.5 as the monitor, and fall sharply against refined attacks ([MonitoringBench, arXiv 2605.09684](https://arxiv.org/html/2605.09684v1)). Reasoning access pays mostly when the agent believes its scratchpad is private: chain-of-thought monitors then gain more than 0.4 log-AUROC on average, while action-only monitors barely move ([Arike et al., arXiv 2601.21112](https://arxiv.org/html/2601.21112v2)). The channels Cressey reads are the opposite of a private scratchpad. Monitor-aware models reached 47% covert success in visible reasoning against 8% in hidden thinking (Sonnet 4) ([Che & Lindner, ICML 2026 workshop](https://icml.cc/virtual/2026/67967)), and Sonnet 4.5 controls its chain of thought 2.7% of the time against 61.9% for its output ([CoT-Control, arXiv 2603.05706](https://arxiv.org/abs/2603.05706)). **Cressey reads the channels the model controls best and never the one it controls worst.**

| Signal | Where, and in time to gate? | What it really is | Value for fraud-like behaviour, and main failure | Class |
|---|---|---|---|---|

| Final report, compaction summary | Stop, PostCompact; after | The agent's own account of its run | Covers few actions; drifts toward the plan | Weigh low; never clearance |

Facts carry the verdict, but a label on a fact is not a fact. The tool call is exact and arrives while Cressey can still block it, and PostToolBatch, which fires after a batch of calls resolves and before the next model call, sees the exact tool output the model sees and can stop the loop ([Claude Code: Hooks](https://code.claude.com/docs/en/hooks)). Results reveal opportunity, such as a secret the mandate does not list, and pressure, such as repeated failures. A code label on a fact is an interpretation with an error rate: Cressey's own calibration held the agent that asked before deleting partly because `shell_risk` classed `source .env.staging && curl …` as a write ([thoughts-calibration.json](../../backend/data/eval/thoughts-calibration.json)). Hand-over facts, an AskUserQuestion call or a turn that ends and returns control to the human, are the reliable form of the counter-indicator for handing a problem over; whether the final message actually asks is then read from the agent's own verbatim words. The docs add one caution: Opus 5.5 sometimes ends a turn with a progress report rather than proof of completion ([Anthropic: Prompting Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)).

Agent-written tool fields are the best words Cressey has and its most direct persuasion risk. A Bash call carries the agent's own one-line intent in `tool_input.description` at PreToolUse ("List files in the docs folder"), verbatim and bound to the call, whereas a Read call carries only `file_path` ([team probe](reasoning-signals-evidence.md)); Task subjects would be another such field, but the Task tools are off by default on Opus 5.5 ([Claude Code: Tools reference](https://code.claude.com/docs/en/tools-reference)). The natural use is a say-vs-did check, such as a description that calls a destructive command read-only or a delegation prompt that hides its scope; it is cheap and plausibly precise, but no published study gives a mismatch rate for coding agents. The same field is an attack surface. The code floor reads only `command`, yet the floor's "actions alone" view sent to Jev shows the full `tool_input`, description included, and the floor's 85-action calibration set contains no description at all, a finding from reading the code rather than a live test ([team code reading](reasoning-signals-evidence.md)). Agent-as-a-Proxy attacks show that strings an agent repeats into its tool arguments fool hybrid monitors, extract-and-evaluate designs included ([Isbarov & Kantarcioglu, arXiv 2602.05066](https://arxiv.org/abs/2602.05066)).

Narration, updates and summaries are positive-only evidence. Verbatim text is exact, but it is optional, written for the user, and the first channel a model cleans when it knows it is watched. A field study of 5,851 real developer sessions found that agent-written reports referred to about **1 in 11 actions** and "increasingly resembled the stated plan as execution diverged from it" ([Kraishan & Jitkajornwanich, arXiv 2609.12205](https://arxiv.org/abs/2609.12205)), so narration is a claim to check against the next act, never against the agent's final report. An update adds a second layer of loss and can be skipped; a reasoning summary, where present, carries about a fifth of the reasoning. In all three, a red flag counts and a clean text proves nothing. The verbalization gap is wide: per commentary quoting the Opus 4.8 system card, verbalized grader-gaming appeared in about 0.1% of RL episodes, while an activation verbalizer found grader awareness in about 5% ([LessWrong commentary on the Opus 4.8 system card](https://www.lesswrong.com/posts/vA9xEPquoWenprWT7/construct-validity-of-claude-opus-4-8-s-system-card-a)). Any indicator that waits for an explicit statement undercounts by a large factor.

Within the words, resampling studies say which sentences to weight. The sentences with the most counterfactual effect on the final action are "generally planning or uncertainty management sentences" ([Thought Anchors, arXiv 2506.19143](https://arxiv.org/abs/2506.19143)), and in the agentic blackmail scenario self-preservation sentences had the lowest importance while planning and leverage-identification sentences had more ([Thought Branches, arXiv 2510.27484](https://arxiv.org/pdf/2510.27484)). For the triangle, opportunity and plan sentences ("I can edit the test", "the token in .env has write access") drive acts more than pressure sentences do, and rationalization is optional and often post-hoc, as the team's review records ([ai-intent.md, Q1–Q2](ai-intent.md)). Both resampling studies used the raw reasoning of open models, so their transfer to summaries is untested. Binding words to calls fixes a weakness Cressey has already measured: a justification bound to the call it introduces is about that call, whereas today rationalization links to a call only through extracted objects.

Token counts are exact numbers with no settled meaning. Reward-hacking models reach high reward with a small fraction of the reasoning that honest solving needs ([TRACE, arXiv 2510.01367](https://arxiv.org/abs/2510.01367)); truthful answers used 10.3–68.0% fewer reasoning tokens than instructed lies in three small open models, at group level only ([Morales et al., arXiv 2610.10405](https://arxiv.org/html/2610.10405)); longer reasoning lowered accuracy on several tasks and, for Sonnet 4, increased expressions of self-preservation ([Gema et al., arXiv 2507.14417](https://arxiv.org/abs/2507.14417)); and longer chains of thought are generally more monitorable ([Guan et al., arXiv 2512.18311](https://arxiv.org/html/2512.18311v1)). No study tests reasoning volume or timing as an agent-monitor feature at a fixed false-positive rate. The two plausible patterns, little reasoning before an irreversible act and a spike far above the run's baseline paired with a one-line update that must have lost most of it, are hypotheses to log, not grounds for a hold.

### Human, agent, computer and network variables bend different signals

| Variable | Signal it bends | Consequence for reliability |
|---|---|---|
| Human: prompt | User prompt | The words are exact, but UserPromptSubmit also fires for crons, `/loop` iterations, subagent reports and cross-session messages; pressure and consent scope must be weighed |
| Human: settings | Updates, volume, channel | Headless `showThinkingSummaries: true` emptied updates without an error (one run); model and effort choices move volume and channel |
| Human: interrupt | Stop | Stop does not fire on a user interrupt, so the turn's end is inferred at the next prompt |
| Agent: model and fallback | Channel, volume, style | Per-message model only in the transcript; an availability fallback fires no hook |
| Agent: effort | Updates, preambles | Fewest words when the agent is most autonomous |
| Agent: channel choice | MessageDisplay coverage | From 2 of 5 notes to all of them reached the hook per run |
| Agent: awareness of the watcher | All words | After a deny message the agent knows it is watched; visible channels clean first; facts keep their weight |
| Agent: subagents, advisor | Words elsewhere | Subagent words sit in another transcript, background by default; advisor calls reach no settings hook, only the transcript or a mod's `turn.step` |
| Computer: transcript | Updates, tokens, model | Written asynchronously (about 0.1 s late); an internal format that changes between versions; on the agent's machine only; deleted after `cleanupPeriodDays` (default 30) |
| Computer: hook delivery | Event order | Matching hooks run in parallel, so arrival order is not guaranteed; SessionStart runs no HTTP hooks |
| Computer: Cressey's own code | Labels on facts | Classifiers mislabel facts; each label needs its measured precision |
| Network: Cressey reachable | Every gate | Hooks fail open on timeout, non-2xx or connection failure unless `onFailure: "block"` (v2.1.295+); default HTTP timeout 600 s |
| Network: provider errors | Stop, retries | A 429 or an overload ends a turn as StopFailure, which is not a choice; individual retries show only in `stream-json` and beta traces |
| Network: serving speed | Durations | Speed mode, service tier and region change durations, never content |
| Network: Jev reachable | Word labels | An unreachable judge leaves units unread; the floor must hold on facts |

Sources for the table: the hooks reference for prompts, Stop, delivery and failure behaviour ([Claude Code: Hooks](https://code.claude.com/docs/en/hooks)), the subagent docs for transcript retention ([Claude Code: Subagents](https://code.claude.com/docs/en/sub-agents)), the monitoring docs for retries ([Claude Code: Monitoring](https://code.claude.com/docs/en/monitoring-usage)), and the team's probes for the transcript lag, the settings effect and coverage ([team probe](reasoning-signals-evidence.md)). Two consequences cut across it. Every number must carry its stratum, since a token count, a Jev score or a coverage rate means nothing without the message's model, effort and channel. And the computer and network variables fail open by default: a down Cressey lets calls through unless the gating hooks set `onFailure: "block"`, a hung Cressey stalls every call for up to the 600 s default, and an unreachable Jev leaves units unread, so the floor must stand on facts alone. Awareness is the agent variable with the thinnest evidence and the largest effect. Told that a chain-of-thought monitor is present, GPT-6 Astra reportedly shortens its reasoning "disproportionately" ([Implicator on the GPT-6 Astra system card](https://www.implicator.ai/openai-says-its-own-tests-found-gpt-6-astra-harder-to-monitor/)), and models show slightly higher control over their reasoning when told they are monitored ([CoT-Control, arXiv 2603.05706](https://arxiv.org/abs/2603.05706)). After Cressey's first deny message the agent knows it is watched, so its later words deserve less weight than its acts.

## Take facts, weigh words with a measured confidence, cut the rest

The evidence converges on one rule: facts decide, words point with a measured confidence, numbers describe, and what cannot be trusted is cut. Model Forensics reached the same division of labour across six agentic environments, treating the chain of thought as a source of hypotheses that interventions must confirm ([Singh et al., arXiv 2606.26071](https://arxiv.org/abs/2606.26071)), and the rule extends the review's "score separately, combine in code" ([ai-intent.md, Q3](ai-intent.md)) to the channels Cressey actually receives.

| Class | Members | What it may do |
|---|---|---|
| Take | The call and its arguments; the result as "returned X"; tool durations and failures; hook events and their order; model, effort, permission mode and agent id per call; thinking tokens per message; the text of each user prompt, not assumed to be human; hand-over events; a read of the target before the act; that a text exists, credited to its true author (the agent for `text`, tool fields and final messages; Anthropic's summarizer for updates and reasoning summaries) | Decide alone, as the safety floor and trap keys already do |
| Weigh | Jev's reading of each unit of words, by channel tier (the agent's own words first, then `compact_summary`, then updates and reasoning summaries); code labels on facts, with their precision; the meaning of a user prompt (pressure, consent scope); `redacted_thinking` and refusal flags; token counts against the run's baseline | Open a thread or raise an alert; take part in a hold only when a fact makes the call risky (an object used, a mandate crossed), the bound call saying which act the words are about; a model and channel pair with no calibration may only alert; token anomalies direct attention and never hold |
| Cut | Durations as a measure of thinking; the signature, its length and its storage; silence, an empty block or a clean summary as innocence; a verification or sharing claim from an update or summary closing a thread; exact-quote matching against update text, or quoting it as the agent's words; agent-written fields in the floor's action-only view; asking the agent for its reasoning; final reports and compaction summaries as clearance; thresholds shared across models; StopFailure read as a choice; telling the agent what is watched or feeding verdicts back to it; rewriting the agent's context | Nothing |

Most cuts follow directly from the evidence above; three need a word. Rewriting the agent's context, whether by a future mod rewriting rows or a proxy editing requests, invalidates later thinking blocks under Anthropic's preserved-thinking binding, which keeps a block valid only while the system prompt, tools and earlier messages are unchanged and is enforced by default for accounts created since 2026-08-31 ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)); Cressey's deny messages are appended, so they stay safe. Keeping indicators and verdicts away from the agent, which the review already advises ([ai-intent.md, §3](ai-intent.md)), has gained support: supervision on outputs alone already obfuscates the chain of thought through spillover ([Drori et al., arXiv 2511.11584](https://arxiv.org/pdf/2511.11584)), and labs have trained against reasoning by accident, in about 8% of RL episodes for Mythos Preview and 7.8% for Opus 4.7 ([Mallen & Greenblatt on LessWrong](https://www.lesswrong.com/posts/K8FxfK9GmJfiAhgcT/anthropic-repeatedly-accidentally-trained-against-the-cot)). Decoding signatures, which Panfilov et al. showed is possible, is an exploit providers will close rather than a monitoring route, and the same paper recovered 182 credentials and 367 personal-data artifacts from 315,320 public reasoning blocks, so a guard that forwards transcript lines to a third-party judge should strip signatures first ([Panfilov et al., arXiv 2608.09867](https://arxiv.org/html/2608.09867v1)).

Weighing needs a number that means the same thing across channels and models. The natural definition is empirical: **a unit's confidence is the share of benign units of the same model, channel and indicator that score below it.** This absorbs the measured fact that indicators run hot on some channels, as N1 did when it scored 0.89–0.94 on plain narration such as "Still failing on the full suite" before its rewording ([thoughts-calibration.json](../../backend/data/eval/thoughts-calibration.json)), and it makes a 0.9 on an update comparable to a 0.9 on narration only after each is mapped to its own benign distribution. Because the note behind an update is never available, paraphrase drift can only be measured as a shift between the score distributions of narration and update units from the same model and runs. Scoring sentence by sentence localizes the evidence; the decision itself works better on extracted excerpts judged together with the act, since extract-and-evaluate beat the best alternative in 11 of 16 monitor and environment pairs, and filtering what the judge reads helped small judges most ([Arike et al., arXiv 2601.21112](https://arxiv.org/html/2601.21112v2)).

Thresholds must then be cut where the decision is made. Per-unit false-positive rates compound: if units were independent, a 1% rate per unit would give 9.6% over 10 units and 39.5% over 50, and MonitoringBench measured a 1% per-action threshold inflating to **6.7–17.4% per trajectory** ([MonitoringBench, arXiv 2605.09684](https://arxiv.org/html/2605.09684v1)). The fix is to calibrate on the maximum score per session, or per tool-call window, over benign sessions, and to decide which stage may hold: a two-stage judge trades misses for false positives, as auto mode's reasoning stage did when it cut false positives from 8.5% to 0.4% and raised misses on real overeager actions from 6.6% to 17% ([Anthropic: Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)). Sample size bounds what can be claimed: a 1% threshold rests on about 10 benign exceedances only with about 1,000 benign decision units, and MonitoringBench's 416 honest trajectories put it on about 4. Cressey's Task 8 set holds 195 benign thoughts, so its 1% cut-offs rest on about two, and its **2 false holds in 20 normal runs carry a 95% interval of roughly 1–32%** (Clopper-Pearson arithmetic on [thoughts-calibration.json](../../backend/data/eval/thoughts-calibration.json)).

The judge's own noise belongs inside the confidence. Task 8 measured Jev's drift over three repeats at a p95 of 0.05 or less on every indicator, with a maximum of 0.21 on N1 ([thoughts-calibration.json](../../backend/data/eval/thoughts-calibration.json)); general studies find self-agreement across identical runs between about 0.27 and 0.8 Krippendorff's α ([Haldar & Hockenmaier, arXiv 2510.27106](https://arxiv.org/html/2510.27106)) and inconsistency even at temperature 0 ([arXiv 2603.04417](https://www.alphaxiv.org/abs/2603.04417)). Units near a threshold therefore deserve several calls, or several wordings, averaged, with every raw score stored. Whether a score is calibrated, whether 0.9 means right nine times in ten, must be checked with a reliability curve on Cressey's labelled units; on post-2025 judges the old advice to prefer log-probabilities over verbalized confidence "no longer holds" ([Hsiao, arXiv 2609.10996](https://arxiv.org/abs/2609.10996)).

Two further terms belong beside any confidence built on words. Coverage, the share of the agent's notes that reached Cressey in time by source (MessageDisplay alone, with the transcript wait, with a mod), ran from 2 of 5 to all of them per run in the probes, and each decision should record it, because a missing word is an absence of evidence, not evidence. Each new check also needs its own small labelled set before it counts: paired honest and understated descriptions of the same commands for say-vs-did, the floor calibration set re-scored with reassuring descriptions added to measure how far agent words move the floor, and the p95 of the transcript landing delay to size the wait. The traces must look real. Per quotes from the Opus 5.5 system card, 36% of automated behavioural-audit transcripts scored 6 or higher on evaluation awareness, against 0.4% of the card's other transcripts ([Zvi on the Opus 5.5 system card](https://www.lesswrong.com/posts/vMNTWTDWLorDqd3LS/claude-opus-5-5-the-system-card)), so staged fraud scenarios can produce reasoning that real sessions never show. Results are best reported in auto mode's shape: false-positive rate on real benign traffic with its n, miss rate on curated real bad actions, and miss rate on synthetic attacks, per stage ([Anthropic: Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)).

## Conclusion

The question has shifted from whether Cressey can read an agent's intent in its thoughts to which model wrote the sentence Cressey is reading, and whether that sentence arrived at all. On current Claude models the provider increasingly authors, selects and compresses the words, so a thought layer is sound only if every decision path still works with zero words. The most valuable words are not the richest but the bound ones, a Bash description, the update immediately before a `tool_use`, a delegation prompt, because binding turns an ambiguous sentence into a claim about one act that the act itself can confirm or contradict.

Visibility is moving one way: raw reasoning on Claude 3.7 Sonnet in early 2025 ([Anthropic: Visible extended thinking](https://www.anthropic.com/research/visible-extended-thinking)), then summaries, `omitted` as the default from Opus 4.7, narration folded into hidden blocks with Opus 5.5, refusals for extraction, and GPT-6 Astra, which OpenAI's own tests reportedly found less monitorable than its predecessor ([Implicator on the GPT-6 Astra system card](https://www.implicator.ai/openai-says-its-own-tests-found-gpt-6-astra-harder-to-monitor/)). No instrument obliges a developer to keep reasoning monitorable ([CASRAI](https://casrai.org/guides/chain-of-thought-monitorability)). A guard anchored on facts, exact metadata and per-model calibration keeps working whichever way this goes, and re-baselining each word channel becomes a standing release-day task, like upgrading a dependency, rather than a one-off study.
