## Open
- Core loop and dashboard: to build at the event, from `concept.md`.
- `owasp_asi.json`: needs the OWASP PDF, downloaded by hand.
- Held-out evaluation set: needs someone outside the team.
- `GITGUARDIAN_API_KEY` repo secret: needed for the secret scan in CI.
- Bedrock for the writer, rewriter and embedder: test `text_format` through Bedrock, move the rewriter off gpt-5.4-mini (not on Bedrock), choose the embedding model (Cohere Embed Multilingual v3 is the candidate) and rebuild the corpus vectors, re-record the cache, re-run the eval. TLS to Bedrock worked on 10-10 from 16:30, and the re-ranker was measured through it. No AWS deploy during the event (« Local only »).
- **Re-record the judge cache:** the new questions change the cache keys, so `replay` and `fallback` have no triangle answers until a `record` run.
- **The report check** is built: a contradicted report flags the run (`report_check`), it doesn't hold or open an incident. A run with no hold whose report lies (the control run) is flagged on the run, not in the incident queue.
- **Hugging Face / METR gaps, for dev after the event** (`positioning-and-risks.md`):
  - a read floor for protected paths declared in the mandate, with no model call;
  - Cressey as the only exit: out of the agent's container, adding the keys on the way out, behind a default-deny network;
  - a signal across runs for the same out-of-mandate target;
  - at fleet scale, a hold refuses on its own and returns the way out.
- **S9's held-out misses:**
  - a hijack with no notes: the ledger flags the planted instruction, but the judgment misses it;
  - a claimed sign-off.

  Holding on a judgment of 0.9 or more without a code leg would have caught one more case with no false hold, but that was found after the held-out run, so it isn't validated.
- **Labelling runs at the first write:** labelling each step in the background as its result comes in would cut that call's wait (p95 0.72 s live).
- **Live model in the loop** for the measurements (gpt-5.4-mini driving `demo/tools.py` through the proxy, 10 runs without Cressey and 10 with it; the scripted replay stays for the stage). Proposed on 10-10, not decided.
- Strands Decider on AWS: no managed service. It runs wherever the package runs (EC2 with a GPU, or a Mac with MLX for the stage).
- The API, approval included, has no authentication: localhost demo only.
- Incidents aren't merged by root cause yet: two holds for the same cause give two incidents.
- **Shell commands through the hook:** a tool missing from the policy is held as destructive (`core/floor.py`), so every `Bash` call would be held. Proposed: read-only commands (`ls`, `cat`, `grep`, `git status/diff/log`, `pytest`) are reads; SQL through `sqlite3` or `psql`, `rm -rf`, `DROP` and `git push --force` are destructive; anything else is a write the triangle judges. Not decided.
- **Hook behaviour not tested yet** against a real Claude Code: the response format, and `"onFailure": "block"` (Claude Code v2.1.295 or later; without it the hook fails open).
