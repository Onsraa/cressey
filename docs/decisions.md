- **Shell commands through the hook (built 10-11, `core/floor.py` `shell_risk`):** a `Bash` command made only of read-only commands (`ls`, `cat`, `grep`, `git status/diff/log`, …) with no redirection to a file (`2>/dev/null` and `2>&1` write nothing) is a read; `rm`, `DROP`, `TRUNCATE`, `DELETE FROM` and `git push --force` are destructive, held whatever the mandate (`may_destroy` names tables, not paths); anything else is a write the triangle judges. - **Holds that matter (built 10-11):** a trap key in a call that only reads is flagged and goes through (an incident, step `alerted`); in a call that writes it is held, and `shell_risk` reads a `curl` that only reads as a read. A hold has three actions: Accept, Reject, and Reject + add reason, where a model drafts the message from the task, the mandate, the tool and the risk class (never the arguments or the agent's words), code checks it and appends the way out, and the human may edit it. A rejection no longer suspends the key: rejected and expired holds are counted per turn (since the user's last prompt, or since the start for MCP, which has none), and the one that reaches the limit (`stuck.rejections` in `policy.yaml`, 3) stops the agent: the key is suspended and that refusal ends with “3 calls were refused. Stop, report what you found, and declare the task impossible: it can't be done with your permissions.” (the number is the configured limit) **Unlock** (`POST /api/runs/{id}/unlock`) or the user's next prompt undoes it; a prompt resets the count even while a call is held, and the key waits for that call's decision. While a call is held the key stays suspended for parallel calls. Why: a rejection steers the agent, which keeps working inside its mandate; three in a turn mean there is no path with its permissions, and then it must stop and report. Limit: the count is per run, and each Claude Code session has its own run.
